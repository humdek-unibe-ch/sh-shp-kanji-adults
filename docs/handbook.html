Section 2

Editing a questionnaire

Consent, demographics and the three pause vignettes are all edited the same way, in the SelfHelp CMS.

  1. Open Module SurveyJS from the admin menu and pick the questionnaire by its CMS name (see the table above).
  2. Edit the question directly in the Creator. To add an answer option, select the question and use the Choices list on the right.
  3. Check every language — German, English, French, Italian, using the language selector at the top. A language left blank shows an empty question to those participants.
  4. Save, then Publish. Saving only stores a draft — Publish is what participants see.
Leave question names alone

Change the visible text freely, but leave question names (like Demo_14) alone once the study is collecting data — renaming splits old and new answers into different columns.

Section 3

Editing the memory task

The four Kanji blocks are built in lab.js. Editing them is copy out, change, copy back.

  1. Open Module LabJS and find the block by its CMS name (see the table above). Copy its configuration text.
  2. Save it as a file on your computer, e.g. task2.json, in plain text — not .txt.
  3. Open labjs.felixhenninger.com and open your file there. Press Preview to run the task as a participant sees it.
  4. Make your change, then export the study as a .json file from the Builder.
  5. Paste it back into Module LabJS over the old configuration, save, and test the whole block with a test code.
Section 4

Getting the data out

The R script from the developer downloads all ten tables and merges them into a single spreadsheet.

  1. Open RStudio. Your token is already filled in, so there is nothing to edit. If you dont have a token, ask the develop team for one.
  2. File → Source R Code… and choose the script. It runs straight away — the first run installs a few packages and takes a few minutes, later runs take seconds.
FileContents
kanji_merged.csvThe study data, one row per participant.
kanji_prize_draw.csvE-mail address and date only.

Running it again overwrites both files with fresh data — it only reads, so run it as often as you like.

Only need one table?

Open Data in the admin menu, pick the table by name, and export it directly — no R needed. The R script produces the same data joined on the participant code, one row per participant.

If it stops with an error

Permission denied writing kanji_merged.csv — the file is open in Excel. Close it and run again.

Could not reach the study website — connect the VPN. Server rejected the token — re-paste it, or ask for a new one. No API token set — the api_key line is empty.

Keep the token private

Do not e-mail the script with the token in it or put it in a shared folder. If someone else needs to export the data, ask the developer for a token of their own rather than sharing yours.

Check the trial count first

If Task1_extra_data_n_trials_learn_A reads 3, that is the short test build, not a real run. Recall counts are lower than learning counts by design — participants learn more pairs than they are tested on.

Packed trial cells

The columns ending in _trials_… hold every trial of that block inside one cell, so Excel shows a single long line instead of numbers. Learning and recall blocks store different fields.

Learning blocks

Task1_extra_data_trials_practice · Task1_…_trials_learn_A · Task3_…_trials_learn_B

Nothing is asked while learning, so each trial records only what was shown and for how long.

FieldMeaning
trialTrial number within the block, starting at 1.
itemWhich Kanji–picture pair was shown, e.g. Baumwolle.
dauer_msHow long the pair stayed on screen, in milliseconds.

Recall blocks

Task2_extra_data_trials_recall_A · Task4_…_trials_recall_B

Here the participant answers and then rates their confidence, so every trial carries both responses and three timings.

The field names differ per block

Each block kept the question numbers from the original Qualtrics study, so the same measurement has a different name depending on the block: practice uses Q22/Q23, recall A uses Q42/Q43, and recall B uses Q2/Q3. The first number of each pair is the image choice, the second the confidence rating.

Reading a packed cell

Each cell is a list of trials wrapped in [ ]. Every trial sits between its own { } and reads as "field":value, separated by commas. One recall cell with two trials looks like this:

[{"trial":1,"item":"Herbst","Auswahl_Q42":"Ast.jpg","Auswahl_Q43":2,
  "Reaktionszeit_Q42_ms":814,"Reaktionszeit_Q43_ms":1545,
  "Reaktionszeit_Q43_ab_Q42_ms":732,"korrekt":0,
  "korrekt_seite":"right","gewaehlt":"left","orig_pos":"1"},
 {"trial":2,"item":"Baumwolle","Auswahl_Q42":"Pflanze.jpg",...}]

So the first trial above tested Herbst, the participant picked Ast.jpg, rated confidence 2, took 814 ms to answer and 732 ms more to rate it, and was wrong (korrekt: 0) because the correct image was on the right and they clicked left.

A learning cell is shorter, because nothing is asked while learning:

[{"trial":1,"item":"Baumwolle","dauer_ms":4991},
 {"trial":2,"item":"Herbst","dauer_ms":4975},
 {"trial":3,"item":"Ast","dauer_ms":4983}]

The *__meta_pages column on questionnaire pages is packed the same way, holding pageNo, start_time and end_time per page.
