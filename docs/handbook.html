List order is counterbalanced

Half the participants learn and recall list A first (AB), the other half list B first (BA). The CMS names still say “Liste A” on tasks 1–2 and “Liste B” on tasks 3–4 — that is the AB order. Task 1 gives each new code the order given out less often so far, so participants alternate AB, BA, AB, … by when they start. Someone who stops part-way still counts, so the groups who finish can end up uneven. A code keeps its order if the page is reloaded.

To test a step directly, add a code to the page address — kanji-adults-pause-1/TEST123 opens pause 1 as if that code had arrived there.

Keep the prize draw separate

The prize draw file has no participant code attached. Never join it back to the study data.

Section 2

Editing a questionnaire

Consent, demographics and the three pause vignettes are all edited the same way, in the SelfHelp CMS.

  1. Open Module SurveyJS from the admin menu and pick the questionnaire by its CMS name (see the table above).
  2. Edit the question directly in the Creator. To add an answer option, select the question and use the Choices list on the right.
  3. Check every language — German, English, French and Italian side by side in the Translation tab. A language left blank shows those participants the German text instead.
  4. Publish. Your edits save on their own as a draft — participants only see them once you press Publish.
Leave question names alone

Change the visible text freely, but leave question names (like Demo_14) alone once the study is collecting data — renaming splits old and new answers into different columns.

Section 3

Editing the memory task

The four Kanji blocks are built in lab.js. Editing them is copy out, change, copy back.

  1. Open Module LabJS and find the block by its CMS name (see the table above). Copy everything in the LabJS JSON box.
  2. Save it as a file on your computer, ending in .json — e.g. task2.json. Notepad will add .txt unless you pick "All files" in the save dialog, and the Builder will not open a .txt.
  3. Open labjs.felixhenninger.com and open your file there. Press Preview to run the task as a participant sees it.
  4. Make your change, then save the study in the Builder. It downloads as a new .json file.
  5. Paste it back. Open the downloaded file in Notepad, copy everything, paste it into the LabJS JSON box over the old text and press Update LabJS. Then run the whole block with a test code.
Section 4

Getting the data out

The R script from the developer downloads the study into separate Excel files: the recall trials laid out like the example datafile, and one file per questionnaire.

  1. Open the script in RStudio. Your token is already filled in, so there is nothing to edit. If you do not have a token, ask the development team for one.
  2. Click Source at the top right of the script. The first run installs a few packages and takes a few minutes, later runs take seconds.

The files land next to the script, sorted into a kanji_data folder:

Running it again overwrites the files with fresh data — it only reads, so run it as often as you like.

Only need one table?

Each questionnaire and recall block is already its own file. The admin menu’s Data page exports a single table directly too, if you want it without running R.

If it stops with an error

Could not write one of the files — it is open in Excel. Close it and run again.

Could not reach the study website — connect the VPN. Server rejected the token — re-paste it, or ask for a new one. No API token set — the api_key line is empty.

Keep the token private

Do not e-mail the script with the token in it or put it in a shared folder. If someone else needs to export the data, ask the developer for a token of their own rather than sharing yours.

The key column

One row per code is the normal case. A code that was submitted twice on the consent page produces two rows for that participant — check for repeated codes before counting.

Check the trial count first

Each list is 30 learning trials and 15 recall trials, plus 2 practice learning and 1 practice recall — 93 in all. Recall is half of learning by design: participants learn more pairs than they are tested on. That is 31 rows per participant in kanji_recall.xlsx; 5 rows means the data came from the earlier short test build, not a real run.

Packed trial cells

The columns ending in _trials_… hold every trial of that block inside one cell, so Excel shows a single long line instead of numbers. You only meet them on the CMS Data page — the recall files have them unpacked, one row per trial, and the learning blocks are not exported. Learning and recall blocks store different fields.

Learning blocks

extra_data_trials_learn_A · extra_data_trials_learn_B

Nothing is asked while learning, so each trial records only what was shown and for how long.

FieldMeaning
stageexperiment for both learning lists.
trialTrial number within the block, starting at 1.
listA or B.
itemWhich Kanji–picture pair was shown, e.g. Baumwolle.
dauer_msHow long the pair stayed on screen, in milliseconds.

Recall blocks

extra_data_trials_practice · extra_data_trials_recall_A · extra_data_trials_recall_B

Here the participant answers and then rates their confidence, so every trial carries both responses, three reaction times and the click timings.

The field names differ per block

Each block kept the question numbers from the original Qualtrics study, so the same measurement has a different name depending on the block: practice uses Q22/Q23, recall A uses Q42/Q43, and recall B uses Q2/Q3. The practice round is a recall block and carries all the same fields. The first number of each pair is the image choice, the second the confidence rating.

Reading a packed cell

Each cell is a list of trials wrapped in [ ]. Every trial sits between its own { } and reads as "field":value, separated by commas. One recall cell with two trials looks like this:

[{"stage":"experiment","trial":1,"list":"A","item":"Herbst",
  "Auswahl_Q42":"Ast.jpg","Auswahl_Q43":2,
  "Reaktionszeit_Q42_ms":814,"Reaktionszeit_Q43_ms":1545,
  "Reaktionszeit_Q43_ab_Q42_ms":732,"korrekt":0,
  "korrekt_seite":"left","gewaehlt":"right","orig_pos":"1",
  "Zeit_First_Click_ms":402,"Zeit_Last_Click_ms":1545,
  "Zeit_Page_Submit_ms":1849,"Click_Count":4},
 {"stage":"experiment","trial":2,"list":"A","item":"Baumwolle",...}]

So the first trial above tested Herbst, the participant picked Ast.jpg, rated confidence 2, took 814 ms to answer and 732 ms more to rate it, and was wrong (korrekt: 0) because the correct image was on the left and they clicked right.

A learning cell is shorter, because nothing is asked while learning:

[{"stage":"experiment","trial":1,"list":"A","item":"Baumwolle","dauer_ms":4991},
 {"stage":"experiment","trial":2,"list":"A","item":"Herbst","dauer_ms":4975},
 {"stage":"experiment","trial":3,"list":"A","item":"Ast","dauer_ms":4983}]

The _meta_pages column on questionnaire pages is packed the same way, holding pageNo, start_time, end_time and duration per page.
